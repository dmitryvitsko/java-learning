# 🎄 NewYearReminder — новогодний поздравитель

## 📋 Задача
Приложение генерирует персональное поздравление для контакта
по его имени. Контакты хранятся в четырёх книгах контактов
по категориям: друзья, коллеги, одногруппники, родственники.
Способ поздравления зависит от типа контакта.

---

## ⚙️ Функциональность
- Хранение контактов четырёх разных типов: телефон, email,
  соцсеть, почтовый адрес
- Каждый тип контакта поздравляется по-своему
- Поиск контакта по имени и отправка поздравления
- Вывод полного списка контактов в книге

---

## 🧠 Теория

### Абстрактный класс как общий контракт
```java
public abstract class Contact {
    private String name;

    public abstract void sendMessage();
    public abstract void print();
}
```
Contact задаёт что каждый контакт ОБЯЗАН уметь - отправлять
сообщение и печатать себя. КАК именно это делать - решает
каждый конкретный тип контакта самостоятельно.

### Четыре разных реализации одного поведения
```java
class Phone extends Contact {
    public void sendMessage() {
        System.out.println("Звоним другу по номеру...");
    }
}

class Email extends Contact {
    public void sendMessage() {
        System.out.println("Отправим картинку на почту...");
    }
}
```
Phone звонит, Email отправляет письмо, SocialNetworkContact
шлёт стикер, Address отправляет открытку по почте. Одно и то
же действие (поздравить) выглядит по-разному в зависимости
от типа контакта. Это полиморфизм в действии.

### Обобщённый класс с ограничением
```java
class ContactBook<T extends Contact> {
    ArrayList<T> contacts = new ArrayList<>();
}
```
ContactBook работает с любым типом который наследует Contact.
Ограничение `T extends Contact` гарантирует что внутри книги
контактов доступны методы getName(), sendMessage(), print() -
они точно есть у любого T благодаря родителю Contact.

### Поиск и вызов через общий тип
```java
public void congratulate(String name) {
    for (T contact : contacts) {
        if (contact.getName().equals(name)) {
            contact.sendMessage(); // вызовется правильная версия метода
        }
    }
}
```
Даже несмотря на то что метод написан один раз для типа T -
вызовется правильная реализация sendMessage() в зависимости
от того какой конкретный объект (Phone, Email и т.д.) хранится
в списке. Это динамическое связывание методов.

## 🛠 Что использовал
- `abstract class Contact` - базовый класс с абстрактными методами
- 4 класса-наследника с собственной реализацией sendMessage() и print()
- `ContactBook<T extends Contact>` - обобщённый класс с ограничением
- Полиморфизм - один и тот же вызов метода
