# 🗂 AdvancedHashMap — двухуровневая хеш-таблица с дженериками

## 📋 Задача
Реализовать хеш-таблицу с двумя ключами разных типов данных.
Хранилище данных - HashMap внутри HashMap.

---

## ⚙️ Функциональность
- `put(key1, key2, value)` - добавить элемент по двум ключам
- `get(key1, key2)` - получить элемент по двум ключам
- `getAll(key1)` - получить все элементы по первому ключу

---

## 🧠 Теория

### Дженерики с несколькими параметрами
```java
class AdvancedHashMap<K1, K2, V> {
    HashMap<K1, HashMap<K2, V>> internalHashMap = new HashMap<>();
}
```
Три обобщённых типа: K1 - первый ключ, K2 - второй ключ,
V - значение. Класс работает с любыми типами данных
которые в него подставят при создании объекта.

### Количество параметров при объявлении и создании должно совпадать
```java
class AdvancedHashMap <K1, K2, V> { ... }

// При создании - ровно столько же типов сколько объявлено в классе
AdvancedHashMap<String, Integer, String> timetable = new AdvancedHashMap<>();
```
Забыть один параметр - частая ошибка при первом знакомстве
с дженериками. Компилятор сразу укажет на несоответствие.

### HashMap внутри HashMap
```java
HashMap<K1, HashMap<K2, V>> internalHashMap = new HashMap<>();
```
Внешняя таблица хранит по первому ключу вложенную таблицу.
Вложенная таблица хранит по второму ключу конечное значение.
Два уровня вложенности - два ключа.

### Важный нюанс: добавление в существующую вложенную таблицу
```java
public void put(K1 key1, K2 key2, V value) {
    HashMap<K2, V> innerHashMap = internalHashMap.get(key1);
    if (innerHashMap == null) {
        innerHashMap = new HashMap<>();
    }
    innerHashMap.put(key2, value); // вне if - выполняется всегда
    internalHashMap.put(key1, innerHashMap);
}
```
Если строку `innerHashMap.put(key2, value)` оставить внутри
блока `if` - второй и последующие элементы с уже существующим
key1 будут теряться. Добавление во вложенную таблицу должно
происходить независимо от того новая она или уже существовала.

### Возвращаемый тип метода тоже обобщённый
```java
public V get(K1 key1, K2 key2) { ... } // не String, а V
```
Метод get() должен возвращать тип V - универсальный,
а не жёстко зафиксированный конкретный тип. Иначе класс
перестаёт быть по-настоящему обобщённым.

---

## 🛠 Что использовал
- Дженерики с тремя параметрами `<K1, K2, V>`
- Вложенная структура `HashMap<K1, HashMap<K2, V>>`
- Проверка на null перед использованием вложенной таблицы
- `ArrayList<>(innerHashMap.values())` - получение всех значений

---

## 💡 Вывод
Дженерики позволяют написать один класс который работает
с любыми типами данных - ключи и значения могут быть чем угодно.
Главная ловушка в таких задачах - не забыть про случай когда
данные добавляются повторно в уже существующую структуру.
