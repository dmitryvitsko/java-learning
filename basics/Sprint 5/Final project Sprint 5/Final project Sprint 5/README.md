# 📦 ShipIt — Финальный проект Спринт 5

## 📋 О проекте
Приложение для управления посылками службы доставки. Три типа
посылок с разной логикой упаковки, доставки и стоимости.
Финальный проект пятого спринта - самая крупная система из
пройденных на курсе.

---

## 🎯 Задача
Спроектировать иерархию классов для трёх типов посылок (стандартная,
хрупкая, скоропортящаяся) с общей логикой в родительском классе
и специфичным поведением в каждом наследнике - без дублирования кода.

---

## ⚙️ Функциональность
- Добавление посылки любого из трёх типов
- Упаковка и доставка всех посылок
- Расчёт общей стоимости доставки
- Трекинг местоположения хрупких посылок
- Хранение посылок в коробках с ограничением по весу
- Проверка истёк ли срок годности скоропортящейся посылки

---

## 🏗 Архитектура

### `Parcel` — абстрактный родительский класс
Хранит общие поля (description, weight, deliveryAddress, sendDay)
и общую логику упаковки, доставки, расчёта стоимости.

### `StandardParcel`, `FragileParcel`, `PerishableParcel`
Наследники Parcel с собственной базовой стоимостью доставки.
FragileParcel дополнительно переопределяет упаковку и реализует
интерфейс Trackable.

### `Trackable` — интерфейс трекинга
Реализован только у FragileParcel - хрупкие посылки можно
отследить по местоположению.

### `ParcelBox<T extends Parcel>` — обобщённый контейнер
Хранит посылки одного типа с ограничением по максимальному весу.

### `DeliveryApp` — точка входа
Консольное меню для управления всей системой.

## 🧠 Что нового освоил

### Абстрактный метод вместо instanceof-цепочки
```java
protected abstract int getBaseCost();

public int calculateDeliveryCost() {
    return (int) (getBaseCost() * getWeight());
}
```
Формула расчёта стоимости - одна, живёт в родителе. А конкретное
число базовой стоимости каждый наследник возвращает сам:
```java
// StandardParcel
private static final int BASE_COST = 2;
protected int getBaseCost() { return BASE_COST; }
```
Никакого instanceof - чистый полиморфизм. Java сама вызовет
нужную версию getBaseCost() в зависимости от реального типа объекта.

### Вынесение общего кода в защищённые методы родителя
```java
protected void printPackaged() {
    System.out.println("Посылка " + this.getDescription() + " упакована");
}
```
Строка "упакована" писалась один раз в родителе. FragileParcel
добавляет свою строку про плёнку и вызывает общий метод:
```java
public void packageItem() {
    System.out.println("... обернута в защитную пленку");
    printPackaged();
}
```

### Интерфейс для необязательного поведения
```java
public interface Trackable {
    void reportStatus(String newLocation);
}

public class FragileParcel extends Parcel implements Trackable {
```
Не все посылки нуждаются в трекинге - только хрупкие. Поэтому
это не часть общей иерархии Parcel, а отдельный интерфейс который
реализует только один конкретный класс. Списки трекаемых объектов
хранятся отдельно через `List<Trackable>`.

### Обобщённый класс с ограничением типа
```java
public class ParcelBox<T extends Parcel> {
    private final List<T> parcels = new ArrayList<>();
}
```
Каждая коробка работает только с одним конкретным типом посылок:
```java
ParcelBox<StandardParcel> standardParcelBox = new ParcelBox<>(50);
```
Ограничение `T extends Parcel` гарантирует доступ к getWeight()
и getDescription() внутри ParcelBox для любого T.

### JUnit тесты на реальную логику приложения
Тесты проверяют расчёт стоимости для разных типов посылок,
логику истечения срока годности и проверку вместимости коробки -
не просто "код компилируется", а что бизнес-логика работает верно.

## 💡 Главный вывод
Абстрактный метод плюс общая формула в родителе - гораздо чище
чем instanceof-проверки или дублирование кода в каждом наследнике.
Это был путь проб и ошибок - от жёстко захардкоженных if/else
через instanceof, до чистого полиморфизма где каждый класс
отвечает только за себя.
