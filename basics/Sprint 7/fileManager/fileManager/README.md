# 📁 FileManager — консольный файловый менеджер

## 📋 Задача
Реализовать консольное приложение для базовых операций с файловой системой: просмотр содержимого директории, создание файлов и директорий, переименование, перемещение и удаление — с корректной обработкой ситуаций, когда указанный путь не существует.

---

## ⚙️ Функциональность
- `ls` — вывести содержимое указанной директории
- `mkdir` — создать директорию
- `touch` — создать файл
- `rename` — переименовать или переместить файл/директорию (`Files.move` работает с произвольным целевым путём, поэтому одна команда закрывает сразу два требования: переименование "на месте" и полный перенос в другую директорию)
- `rm_file` — удалить файл или пустую директорию по указанному пути
- `exit` — выход из программы

---

## 🧠 Теория

### Path как абстракция над строкой пути
```java
Path path = Paths.get(enteredPath);
```
Вместо того чтобы работать со строкой напрямую, `Paths.get()` превращает её в объект `Path` — платформенно-независимое представление пути, с которым дальше работают все методы из `java.nio.file.Files`.

### Проверка существования перед операцией
```java
if (Files.exists(path)) {
    ...
} else {
    System.out.println("Указанная директория не существует.");
}
```
Перед каждой потенциально "опасной" операцией (просмотр, переименование, удаление) идёт проверка `Files.exists()` — это позволяет не ловить исключение там, где можно было предвидеть проблему заранее, и сразу дать пользователю понятное сообщение.

### Files.move как переименование и как перемещение одновременно
```java
Files.move(path, Paths.get(newName), StandardCopyOption.REPLACE_EXISTING);
```
`Files.move` не делает разницы между "переименовать в той же папке" и "переместить в другую" — в обоих случаях это перенос из одного пути в другой. Если пользователь вводит просто новое имя — файл остаётся на месте под новым именем; если вводит путь с другой директорией — файл физически переезжает туда. `StandardCopyOption.REPLACE_EXISTING` разрешает перезаписать файл, если по целевому пути уже что-то есть.

### Files.delete работает и с файлами, и с пустыми директориями
```java
Files.delete(path);
```
Метод не привязан к типу — если `path` указывает на файл, удалится файл; если на пустую директорию — удалится директория. Благодаря этому одна операция удаления закрывает оба случая из требований задачи.

### try-catch вокруг каждой файловой операции
```java
try {
    Files.createDirectory(path);
    System.out.println("Директория успешно создана.");
} catch (IOException e) {
    System.out.println("Ошибка при создании директории.");
    e.printStackTrace();
}
```
Методы `java.nio.file.Files` бросают проверяемый `IOException` — компилятор обязывает обработать его в месте вызова. Каждая операция обёрнута в свой `try-catch`, чтобы ошибка в одной команде (например, нет прав на запись) не обрушивала всю программу и не мешала пользователю попробовать другую команду.

### Цикл меню вместо однократного выполнения
```java
while (true) {
    printMenu();
    String command = scanner.nextLine();
    if (command.equals("exit")) {
        break;
    }
    ...
}
```
Бесконечный цикл с выходом по команде `exit` превращает приложение в полноценную интерактивную оболочку, а не в одноразовый скрипт — пользователь может выполнить сколько угодно операций за один запуск.

---

## 🛠 Что использовал
- `java.nio.file.Path` / `Paths.get()` для представления пути к файлу или директории
- `Files.exists()` для предварительной проверки перед операцией
- `Files.createDirectory()` / `Files.createFile()` для создания директорий и файлов
- `Files.move()` с `StandardCopyOption.REPLACE_EXISTING` — для переименования и полного перемещения
- `Files.delete()` — для удаления как файлов, так и пустых директорий
- `switch` по строковой команде для маршрутизации действий пользователя
- Обработку `IOException` в каждой файловой операции

---

## 💡 Вывод
Задача показывает, что API `java.nio.file` покрывает все типовые операции файловой системы небольшим набором методов: `exists`, `createDirectory`, `createFile`, `move`, `delete`. При этом `move` универсален — не нужно писать отдельную логику для переименования и для перемещения, это буквально одна и та же операция с разным целевым путём.
